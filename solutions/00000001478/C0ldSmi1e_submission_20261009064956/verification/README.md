# Evidence index

The final portable verifier run is in `engineering-proof/`; the final unit, compiled rejection, and dependency controls are in `engineering-controls/`. Their `result.json` files contain the full actual command records, including stdout/stderr and exit status. Separate command directories provide the same raw output for inspection. An intentional fixture audit exit of 1 is a successful rejection control, not a failed mathematical build.

`root-reproduction/` contains the coordinator's independent fresh verifier result, inventory, complete safe dependency closure, dependency check summaries, and separate raw full-build/strict-replay records. Its `result.json` also includes every dependency command record. `root-validation.json` records the coordinator's separate reading, reproduction, and rehashing of the original output manifests. This receipt predates final package/publication review and says so explicitly.

`compiled-inventory.json` is the expected complete inventory independently measured from frozen revision 2 before the portable run. Both final fresh verifier runs reproduce it. `source-manifest.json` binds every verifier input; `pinned-dependencies.json` preserves all nine dependency pins. The final package may additionally carry a whole-payload manifest prepared after final review.

`author-freeze.json` is the untouched raw revision-2 author freeze. `author-freeze-v1.json` preserves its referenced previous freeze. `author-original-lakefile.toml` preserves the original configuration, and `author-mathematics.md` preserves the exact current author's mathematical explanation and provenance. `author-v2/` includes the final author receipts and build/strict logs, mapped to their original absolute paths and exact hashes by `author-evidence-map.json`. Its verification-only `Inventory.lean` has the packaged name `Inventory.lean.txt`, with identical bytes, and is not an imported submission module.

`engineering-provenance.json` records the generic tooling reuse, pre-freeze preparation, post-release application, role separation, and local attempt locations. `engineering-attempts-v1.json` records the rejected first revision and diagnostic counts. `engineering-release-acceptance-v2.json` and `engineering-v1-v2.diff` record the exact five compilation annotations and unchanged mathematics. No failed attempt is represented as a passing result. Failed projects, provisional probe files, and preliminary baseline build directories remain local at the paths in these records; they are not duplicated in the submission.

`root-frozen-release.json`, `root-verifier-code-review-v1.json`, `author-rule-equivalence.json`, and `root-report-review.json` retain the supplied coordinator receipts. The verifier code changed from that initial code review only in the two frozen revision hashes. Report source and PDF hashes are recorded in the report receipt; the engineering task copied both files without regenerating them.

`selected-raw-records.json` maps the included selected final command/result files to their original run paths and SHA256 values. The original runs' full `SHA256SUMS.json` files also cover temporary project copies and are retained locally; they are not included as if those omitted files were packaged. Fresh-project caches, generated negative-control Lean modules, synthetic Git fixture repositories, and duplicate source copies are omitted. Fixture source strings remain visible in the control script and actual result records so that the expected failures can be reviewed.

The absolute paths and timestamps are historical execution provenance, not installation requirements. Reproduction uses the relative packaged inputs and the explicit dependency/runtime paths supplied to the scripts. Engineering verification, author self-checks, and independent semantic review are separate evidence roles. No record claims maintainer acceptance.
