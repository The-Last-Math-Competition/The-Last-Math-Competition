# Independent verification of conjecture 00000000069

The submitted proof refutes the stated **L1** approximation rate. It proves an upper bound for the actual infimum over all real polynomials of the specified degree, then rules out every nonzero constant in the ratio asymptotic `E_n ~ B/n`. The original bilingual statement and complete contribution rules are retained under `source/`.

The author derived the construction in a fresh context restricted to those inputs and stock libraries. A separate reviewer read the argument, all mathematical source files and the complete report. The parent independently read the same material, rebuilt the proof and examined the resulting declaration dependencies. The independent reviews in this directory record their exact source hashes and scope. None of these local checks constitutes maintainer acceptance.

## Verification performed

- Rebuilt all six mathematical modules from source in a separate project using Lean 4.19.0 and the pinned stock Mathlib v4.19.0 dependencies. No authored compiled artifact was copied into that project.
- Replayed every mathematical source and the Lake configuration with warnings treated as errors.
- Inventoried all 79 declarations originating in the mathematical modules, including generated declarations and declarations outside public namespaces. Checked the full dependency closure of all 75 kernel-safe declarations: 36,184 distinct logical dependencies, with no missing dependency. The larger combined inventory contains 36,193 entries, including compiler runtime artifacts. Only `propext`, `Classical.choice` and `Quot.sound` occur as logical axioms; no kernel-safe declaration depends on unsafe code.
- Matched 4,081 imported compiled modules to the supplied stock library or Lean runtime. Checked the pinned revisions and tracked source contents of all nine dependency packages and confirmed the shared stock Git indexes remained unchanged.
- Tested the audit with a valid control and controls containing an unrelated custom axiom, an indirect custom axiom, an unfinished proof, a native decision procedure and an authored unsafe definition. The valid control passed; every invalid control was rejected. A warning-strict replay also rejected the unfinished proof.
- Replayed the supplied `verification/verify.sh` independently after the final manifest name was normalized to `tlmc69`. This rebuilt the final configuration, replayed all mathematical sources and `verification/Axioms.lean`, confirmed all 44 named lemma/theorem axiom outputs and ran the exact-input/source-integrity utility. The mathematical sources and dependency pins were unchanged from the independent fresh build.
- Read the complete LaTeX report, compiled it with the desktop editor compiler, exported the PDF with Tectonic and visually inspected all four pages. The definitions, constants, quantifiers, theorem and report agree. No numerical auxiliary computation is required by this proof.

## Compiler-generated runtime declarations

The inventory includes four unsafe compilation-stage helpers generated by Lean for the natural-number pattern matcher and splitter in `Q`. These were not authored unsafe declarations. They have no axioms, and none is reachable from any of the 75 kernel-safe declarations. Their compiler-only pseudo-symbols are retained in the evidence rather than represented as resolved logical dependencies.

The raw engineering summary deliberately preserves the status `PASS_PENDING_RUNTIME_HELPER_CLASSIFICATION`. The separate `independent/RUNTIME-CLASSIFICATION.json` records the completed review of all four exact helper names and resolves that pending classification. The logical dependency audit itself has zero failures. The generated helpers are not proof premises or native-decision shortcuts.

## Reproduction

The portable author verification commands are documented in the root README:

```sh
lake build
sh verification/verify.sh
```

The additional offline verifier is supplied under `verification/independent/`. On macOS, with an unchanged, fully populated stock Mathlib v4.19.0 checkout and its pinned packages/caches, run:

```sh
python3 verification/independent/verify.py verify \
  . verification/independent/FROZEN.json \
  /absolute/path/to/stock/mathlib \
  /absolute/path/to/lean-4.19.0/bin \
  /absolute/path/to/a/new/review-directory
```

The last directory must not already exist. This tool uses macOS copy-on-write copies and blocks unexpected network commands during its build. It inventories every active Lean module, rather than trusting a fixed namespace or a selected final theorem alone. Its generated negative controls intentionally contain invalid proof mechanisms and remain outside the mathematical submission modules.

`independent/FROZEN.json` binds the final active Lean sources and project configuration. The archived original fresh-build input differs from the final configuration only in the root manifest's package name (`tlmc_neutral` became `tlmc69`); all package revisions and mathematical source bytes are identical. The final auxiliary replay records that metadata change explicitly.

`independent/engineering-evidence.tar.gz` contains the exact fresh-build input, command receipts, full declaration graph, import identities, stock source inventories, control results, runtime classification and final auxiliary replay. Its internal manifest was checked by reopening and hashing every member. `independent/ARCHIVE.json` records its outer checksum. `independent/DECLARATIONS.json` is a compact inventory for convenient inspection.

## Verification limits

The authored proof was rebuilt; the entire stock Mathlib library was not rebuilt, and the supplied Lean runtime was not bootstrapped. Cached dependency imports were matched to the supplied stock bytes, and package source identities were checked separately. Repository eligibility and final publication checks are distinct from mathematical verification. A local PASS does not imply CI execution, maintainer review or competition acceptance.
