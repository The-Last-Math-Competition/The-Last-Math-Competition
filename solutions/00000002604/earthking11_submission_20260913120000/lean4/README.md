# Lean 4 formalisation (conjecture 00000002604)

Core Lean 4 only: `import Std`, **no Mathlib**, no `sorry`, no `axiom`, no
`native_decide`. Toolchain pinned in `lean-toolchain` to
`leanprover/lean4:v4.33.1`.

## Contents

- `Main.lean`
  - `leP`, `leQ : Fin 4 → Fin 4 → Bool` — the two posets
    `P : 0<1<2` with `3` isolated, and `Q : 0<2, 0<3, 1<2` (reflexive-transitive
    closure).
  - `idealCountVector (le) : List Nat` — for each size `s`, the number of
    down-closed subsets of `Fin 4` of cardinality `s`, enumerated over the `16`
    bitmasks. `Finset` is Mathlib, so subsets are encoded as `Nat` bitmasks and
    all enumeration uses `List`/`Fin`/`Nat`/`Bool`.
  - `vectorP`, `vectorQ` — both vectors equal `[1,2,2,2,1]`.
  - `vectors_equal : idealCountVector leP = idealCountVector leQ`.
  - `perms : List (List Nat)` — all `24` bijections `Fin 4 → Fin 4`, generated by
    an explicit `permutations` function (`List.permutations` is not in Std).
  - `IsIsoPerm` — checks bijectivity together with preservation/reflection of the
    order relation.
  - `not_isomorphic : perms.all (fun p => IsIsoPerm leP leQ p) = false` — no
    bijection is an order isomorphism.
  - `conjecture_00000002604_false` — packages the two facts.
- `Check.lean` — `import Main` plus `#print axioms` for each theorem.

## Build and audit

```sh
export PATH="/opt/homebrew/bin:$PATH"
cd lean4
lake build
lake env lean Check.lean
```

`lake build` completes successfully. The axiom audit reports that every theorem
depends only on `[propext]` (a standard Lean axiom, used by `decide`); there is no
`sorryAx` and no `Lean.ofReduceBool`.

## Note

The `n = 4` collision is formalised because it is smaller and cleaner; the same
phenomenon on `n = 5` and the minimality search are handled in `reproduce.py` and
`main.tex`.
